# AXI4-Lite 协议与内存约定

本指南详细说明了本 CPU 课程框架中采用的 **AXI4-Lite** 总线协议规范、内存布局以及 CPU 与模拟器之间的交互约定。

---

## 1. 概述与核心概念

AXI4-Lite 是 ARM AMBA 规范中的一种轻量级内存映射总线协议，适用于控制寄存器访问及简单的存储器读写。它的主要特征包括：
- **点对点通信**：连接 Master（主设备，即你的 CPU）与 Slave（从设备，即我们提供的外部内存仿真模型）。
- **通道相互独立**：总线分为 5 个独立的单向事务通道，读写通道分离，支持全双工并发。
- **单次突发（No Burst）**：每次事务固定只传输一次 32 位数据，无需维护复杂的突发长度（Burst Length）。
- **统一握手机制**：每个通道均使用标准的 `VALID / READY` 双向握手机制。

---

## 2. 五大独立通道与接口定义

AXI4-Lite 总线由 **读地址 (AR)**、**读数据 (R)**、**写地址 (AW)**、**写数据 (W)**、**写响应 (B)** 5 个独立通道组成。

顶层模块 `student_top` 的信号方向定义如下（`M->S` 表示 CPU 输出，`M<-S` 表示 CPU 输入）：

| 通道 | 信号名称 | 方向 | 位宽 | 描述 |
| :--- | :--- | :---: | :---: | :--- |
| **全局** | `clock` | M->S | 1 | 内存同步时钟（上升沿采样） |
| | `reset` | M->S | 1 | 同步复位信号，高电平有效（框架在启动时保持 5 周期高电平） |
| **读地址 (AR)** | `araddr` | M->S | 32 | 读请求的目标物理地址（必须按 4 字节自然对齐） |
| | `arvalid` | M->S | 1 | 读地址有效指示，由 CPU 驱动 |
| | `arready` | M<-S | 1 | 内存是否准备好接收读地址 |
| **读数据 (R)** | `rdata` | M<-S | 32 | 读出的 32 位数据 |
| | `rresp` | M<-S | 2 | 读响应状态码（`2'b00` = OKAY） |
| | `rvalid` | M<-S | 1 | 读数据有效指示，由内存驱动 |
| | `rready` | M->S | 1 | CPU 是否准备好接收读数据 |
| **写地址 (AW)** | `awaddr` | M->S | 32 | 写请求的目标物理地址（必须按 4 字节自然对齐） |
| | `awvalid` | M->S | 1 | 写地址有效指示，由 CPU 驱动 |
| | `awready` | M<-S | 1 | 内存是否准备好接收写地址 |
| **写数据 (W)** | `wdata` | M->S | 32 | 写入的 32 位数据 |
| | `wstrb` | M->S | 4 | 字节写使能掩码（Byte Strobe，每位对应 1 个字节） |
| | `wvalid` | M->S | 1 | 写数据有效指示，由 CPU 驱动 |
| | `wready` | M<-S | 1 | 内存是否准备好接收写数据 |
| **写响应 (B)** | `bresp` | M<-S | 2 | 写响应状态码（`2'b00` = OKAY） |
| | `bvalid` | M<-S | 1 | 写响应有效指示，由内存驱动 |
| | `bready` | M->S | 1 | CPU 是否准备好接收写响应 |

> [!NOTE]
> 标准 AXI4-Lite 中的保护信号 `ARPROT` 与 `AWPROT` 在本课程仿真器中未连接，你的 CPU 可以不声明该端口或直接置为 0。

## 3. Valid / Ready 握手机制

AXI 协议的核心在于每个通道的独立握手。理解并遵守以下握手黄金法则是避免总线死锁的关键：

### 握手规则

1. **事务生效条件（Fire）**：当且仅当同一通道上的 `VALID` 和 `READY` 在**同一个时钟上升沿同时为高**时，传输才算成功发生（Handshake Fire）。
   $$\text{Transfer Occurs} \iff \text{VALID} \land \text{READY} \land \text{posedge clock}$$
2. **VALID 的稳定性（Stability）**：发送方一旦将 `VALID` 拉高，在握手成功完成之前，不能撤回 VALID，且通道上的伴随有效载荷（如 `ADDR`、`DATA`、`WSTRB`）应保持稳定，不得中途更改。
3. **消除组合逻辑环路（No Circular Dependency）**：
   - 发送方不应等待接收方的 `READY` 变高后才拉高 `VALID`（即 `VALID` 不能组合依赖 `READY`）。
   - 接收方可以先拉高 `READY`，也可以等待 `VALID` 拉高之后再拉高 `READY`。

## 4. 事务流程与时序图解

### 4.1 读事务流程 (Read Transaction)

一个完整的读事务由两个阶段组成：
1. **地址阶段**：Master 在 AR 通道发送目标地址并置高 `arvalid`。Slave 在 `arready` 为高时接收地址，完成地址握手。
2. **数据阶段**：Slave 根据地址从内存中读出数据，在经过固定的内存延迟后，在 R 通道置高 `rvalid` 并驱动 `rdata` 与 `rresp`。Master 置高 `rready` 确认接收，完成数据握手。

---

### 4.2 写事务流程 (Write Transaction)

写事务涉及 **写地址 (AW)**、**写数据 (W)** 以及 **写响应 (B)** 三个通道：
1. **地址与数据发送**：Master 在 AW 通道发送写地址，并在 W 通道发送写数据与字节掩码 `wstrb`。
2. **写响应接收**：Slave 接收到写请求后执行写操作，随后在 B 通道拉高 `bvalid`，Master 通过 `bready` 接收响应 `bresp`。

> [!IMPORTANT]
> **AW 通道与 W 通道相互独立！**
> 协议不限制 AW 和 W 谁先到达：
> - **同周期握手**：`awvalid && awready` 与 `wvalid && wready` 在同一周期发生；
> - **AW 先于 W 握手**：地址先被接收，数据在稍后周期握手；
> - **W 先于 AW 握手**：数据先被接收，地址在稍后周期握手。
>
> 只有当写地址和写数据**两者均已握手成功**之后，从机才会真正将请求压入写入队列并处理。但你最好保持 `awvalid` 和 `wvalid` 信号永远一致。

## 6. 内存从机行为与仿真约束

在课程仿真器 (`scripts/sim.cpp`) 中，内存从机具备以下行为特性：

### 6.1 内存空间与容量
- **容量**：小端 256 MiB RAM，有效地址范围为 `0x00000000`–`0x0fffffff`。
- **未加载区域**：未被二进制程序覆盖的 RAM 空间在仿真初始时全部置零。
- **退出 MMIO 虚拟地址**：`0x80000000`（超出 256 MiB RAM 范围，为专用退出地址）。

### 6.2 队列深度与服务模型
- 从机在 AR、AW、W、R、B 5 个通道均维护深度为 **16** 的 FIFO 队列。
- **握手接受能力**：只要对应 FIFO 未满，从机的 `ready` 信号在非复位状态下保持为 1。
- **服务节奏**：每个时钟周期最多从队列取出一个读请求和一个写请求开始服务。

### 6.3 内存访问延迟 (Latency)
- 事务在握手成功的**下一个周期**才会进入服务流程。
- 从开始服务到响应数据可见，默认固定经历 **10 个周期**（`due = cycle + latency`）。可以通过命令行 `--latency <N>` 或 `make run LATENCY=<N>` 调整该参数。

### 6.4 响应状态码 (`rresp` / `bresp`)
- `2'b00` (**OKAY**)：正常响应。
- `2'b10` (**SLVERR**)：从机错误。产生原因包括：
  - 地址未对齐到 4 字节边界（`addr[1:0] != 2'b00`）；
  - 向退出地址 `0x80000000` 发起写操作，但 `wstrb != 4'b1111`（退出必须是完整的 32 位写）。
- `2'b11` (**DECERR**)：地址译码错误。访问地址超过 256 MiB 且不等于 `0x80000000`。

### 6.5 程序终止与退出协议 (Halt Protocol)
- 程序运行结束时，CPU 必须通过一条向地址 **`0x80000000` 的 32 位写指令**通知从机。
- 写入条件：
  - `awaddr = 32'h80000000`
  - `wstrb  = 4'b1111` (`4'hf`)
  - `wdata  = {返回值[31:0]}`
- **仿真终止时刻**：仿真器在写响应通道握手成功（`bvalid && bready` 为高）的瞬间捕获返回值并结束仿真。
- **正确性判定**：最终退出返回值必须与测试用例的标准答案一致。
